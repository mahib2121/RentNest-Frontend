## 4. Auth mechanism

**File:** `proxy.ts` (at project root, not under `app/`) — Next.js 16's renamed middleware convention. Exports `proxy(request: NextRequest)` and a `config.matcher`.

### Token storage
**Cookies only — `httpOnly`, never localStorage.**
- `accessToken` cookie: `httpOnly: true`, `secure: process.env.NODE_ENV === "production"`, `maxAge: 60*60*24` (1 day), `sameSite: "lax"`, `path: "/"`.
- `refreshToken` cookie: same flags, `maxAge: 60*60*24*7` (7 days).
- Set by `loginAction` (`app/(authGroup)/_actions/authAction.ts`) via `cookies().set(...)`; deleted by `logout()`.
- The proxy re-writes `accessToken` with `path: "/"` when it refreshes.

### Public routes (`PUBLIC_ROUTES`)
```
"/", "/properties", "/payment", "/news",
"/robots.txt", "/sitemap.xml", "/not-found"
```
Matching helper `isRoute(routes)` uses exact equality OR `pathname.startsWith(route + "/")` (except `"/"`, which is exact-only).

Note: `"/news"` is listed as public but **no `/news` route exists** in the app.

### Auth routes (`AUTH_ROUTES`)
`"/login"`, `"/register"` — a signed-in user hitting either is redirected to their role dashboard.

### Role routing tables

```ts
const ROLE_DASHBOARDS = {
  TENANT:   "/tenant-dashboard",
  LANDLORD: "/landlord-dashboard",
  ADMIN:    "/admin-dashboard",
};

const ROLE_PROTECTED_ROUTES = {
  TENANT:   "/tenant-dashboard",
  LANDLORD: "/landlord-dashboard",
  ADMIN:    "/admin-dashboard",
};
```
- If not signed in and the path is neither public nor an auth route → `redirect("/login")`.
- If signed in and the path falls under a protected role prefix but `userRole !== requiredRole` → `redirect("/not-found")`.

### Token verification
`utils/jwt.ts` → `verifyToken(token, secret)` wraps `jsonwebtoken.verify` in a try/catch and **never throws**. Returns `{success, data?: JwtPayload, error?: string}`. Secrets come from `process.env.JWT_ACCESS_SECRET` / `process.env.JWT_REFRESH_SECRET`.

### Refresh-token recovery flow
1. Read `accessToken` + `refreshToken` from `request.cookies`.
2. `verifyToken(accessToken, JWT_ACCESS_SECRET)`.
3. **On success:** `currentAccessToken = accessToken`, `userRole = payload.role`.
4. **On failure (missing / expired / old secret):**
   a. `verifyToken(refreshToken, JWT_REFRESH_SECRET)`.
   b. If the refresh token verifies → `requestNewAccessToken(refreshToken)`:
      - `POST ${APIurl}/api/auth/refresh-token` with header `Cookie: refreshToken=<token>`, `cache: "no-store"`.
      - Expects `{success: true, data: {accessToken: "..."}}`.
      - The returned token is **re-verified** locally with the access secret. If it fails → `clearAccessToken = true` (the backend handed back an untrusted token).
   c. If refresh fails or the backend rejects it → `clearAccessToken = true`.
   d. If there was an access token but no usable refresh token → `clearAccessToken = true` (drop the stale cookie).
5. `applyCookies(response)` is applied to **every** response path:
   - `setAccessToken` → sets the new `accessToken` cookie (httpOnly, secure in prod, maxAge 1 day, sameSite lax, path `/`).
   - `clearAccessToken` → **deletes both** `accessToken` and `refreshToken`.

Key invariant documented in the code: `currentAccessToken` only ever holds a **verified** token, so `isSignedIn` cannot be true for a stale or tampered cookie.

if (pathname.startsWith("/properties/load-test")) {
  if (process.env.ENABLE_LOAD_TEST !== "true") {
    return NextResponse.rewrite(new URL("/not-found", request.url));
  }
}
```
- Lives under `/properties`, which is a public route, so without this gate the virtualisation load-test page would ship as a live page.
- The proxy answers **before** anything is rendered and rewrites to `/not-found` (a rewrite, not a redirect — the URL stays `/properties/load-test`).
- Gate opens only when `ENABLE_LOAD_TEST === "true"` (string compare, exact).
- **`ENABLE_LOAD_TEST` is NOT present in `.env`** (keys are only `APIurl`, `JWT_ACCESS_SECRET`, `JWT_REFRESH_SECRET`, `NEXT_PUBLIC_BACKEND_API_URL`), so the gate is closed by default.
- The load-test page itself **does not exist** in `app/` — only the proxy rule references it.

export const config = {
  matcher: ["/((?!api|_next/static|favicon.ico|_next/image|.*\\.png$).*)"],

```
Excludes `api`, `_next/static`, `favicon.ico`, `_next/image`, and `.png` files.

- `app/(dashboardGroup)/layout.tsx` calls `getMe()`; if `user.data?.profile` is missing it renders `children` **without** the navbar/sidebar.

- `app/(authGroup)/layout.tsx` calls `getMe()` **without** `connection()`.

## 11. Notable components detail

### `components/ui/virtual-table.tsx` — `VirtualTable<T>` (custom, not shadcn)

**Contract**
```ts
type VirtualTableColumn<T> = {
  key: string;
  label: string;
  width?: string;              // "180px" | "20%" — unset columns share the remainder
  align?: "left" | "right";
  renderHeader?: () => React.ReactNode;   // defaults to a plain label
  renderCell: (row: T) => React.ReactNode;
};

type VirtualTableProps<T> = {
  columns: VirtualTableColumn<T>[];
  rows: T[];
  rowKey: (row: T) => string;
  height?: number;             // default 560
  overscan?: number;           // default 8
  empty?: React.ReactNode;
  stickyHeader?: boolean;      // default true
  className?: string;
};
```

**How it works**
- Built on `@tanstack/react-virtual`'s `useVirtualizer`: `count: rows.length`, `getScrollElement: () => scrollRef.current`, `estimateSize: () => 57`, `overscan`, `initialRect: {width: 1024, height}`, `getItemKey: (index) => rowKey(rows[index])`.
- **The table stays a real `<table>`**: `<thead>` is a normal sticky header (`sticky top-0 z-10 bg-paper-raised`), and body rows are real `<tr>` elements inside a `<tbody>`.
- The `<tbody>` is a **spacer** of the full scroll height (`height: virtualizer.getTotalSize()px; position: relative; display: block`). Each row is `position: absolute; top: 0; left: 0; transform: translateY(virtualRow.start)px; display: table; tableLayout: fixed`.
- **Width management** — because absolutely-positioned rows drop out of the table's column layout, widths are computed manually and applied identically to the `<colgroup>`, the `<th>`s, and every `<td>`: declared widths are parsed as px; the remainder (`tableWidth - fixedWidth`) is split equally among the flexible columns, floored at 120px. The table's own width is measured with a `ResizeObserver` on the `<table>` element (`ESTIMATED_TABLE_WIDTH = 1024` initial, `MIN_TABLE_WIDTH = 760` so it scrolls rather than crushes).
- **Row heights are measured, not assumed** — `virtualizer.measureElement` is the `ref` on each `<tr>` and `data-index` is set, so a row that wraps to two lines doesn't overlap the next.
- **Scroll handling** — `onScroll={measureRows}` where `measureRows = useRafThrottle(() => virtualizer.measure())`; the rAF throttle collapses the scroll storm into one measurement per frame.
- **First-render fallback** — if `virtualRows.length === 0` (server render, or before the element is measured), it falls back to `rows.slice(0, ceil(height/57))` rows positioned at `index * 57` so the table is never blank.
- **Empty state** — if `rows.length === 0 && empty`, renders `<div className={className}>{empty}</div>` and nothing else.
- Row hover: `transition-colors duration-150 ease-out hover:bg-secondary/60`; row border `border-b border-line`.

**Consumers:** public `properties/_components/PropertiesTable.tsx` (`height=620`, `overscan=10`), admin `PropertiesTable.tsx` (`560/8`), admin `RentalRequestsTable.tsx` (`560/8`), admin `UsersTable.tsx` (`560/8`), landlord `PropertiesTable.tsx` (`520/8`).
